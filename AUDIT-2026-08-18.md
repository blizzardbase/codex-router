## Verdict

**Safe to fork and pin, with four named changes.**

This is not a malware finding. It is a well built local router by an author who
thought about credential separation. The residual risk is design decisions with
real blast radius, not hidden behaviour.

Clean on all of: no telemetry, no analytics, no author controlled domain in any
code path, no obfuscation, no `eval`, no dynamic code loading, no auto update
ping, and no committed secret across 584 commits of full history.

## The finding that matters most

### 1. HIGH, default ON. The router can spend the ChatGPT subscription.

`src/codex-native-session.mjs:24,34,137` and `src/router.mjs:382-418`

It reads `$CODEX_HOME/auth.json`, takes `access_token` and `account_id`, and
attaches them as a fallback when a caller presents no upstream credential of its
own. Destination is `https://chatgpt.com/backend-api/codex`.

**The token does not leak to third parties.** `src/api-forwarder.mjs:744-747`
strips `authorization`, `x-api-key`, `chatgpt-account-id` and every `x-codex-*`
and `x-openai-*` header before any external call. That was checked, not assumed.

**What it means for Harish.** Any local process holding the caller key can spend
his ChatGPT plan, and the DeepSeek Harness and Gemini CLI integrations can be
pointed at his Codex subscription from a client that is not Codex. **That is the
OpenAI shaped version of the exact enforcement risk he is avoiding with
Anthropic.**

**The off switch is broken in a specific way.**
`CODEX_ROUTER_NATIVE_SESSION_FALLBACK=0` is an environment variable only, and
`src/service-macos.mjs:47-80` does not write it into the generated launchd
plist. Children do inherit `process.env`, so adding it to the plist works, but
**every install and update regenerates that plist and silently drops the edit.**

The author reasoned correctly about this elsewhere: `src/discovery-mode.mjs:8-21`
persists discovery mode to a file precisely because an env var dies with the
setup run. The same reasoning was not applied here.

**Finding 2 in detail**, because it has no off switch. `src/codex-app-tools.mjs`
and `src/router.mjs:2002` merge Codex's native app tool definitions into requests
going to routed providers, unconditionally. The set includes
`automation_update` (create recurring scheduled runs), `plugin_management`,
`uninstall_plugin`, `send_message_to_thread`, `read_thread_terminal` and
`create_thread`. The router never executes these; Codex does. So prompt injection
reaching a routed model has the Codex automation and plugin surface in reach, on
a provider Harish may trust less than OpenAI.

**Finding 3, with credit where due.** Choosing the Kimi OAuth, Grok OAuth or
DeepSeek Harness path runs `npm install -g` with no version pin. But the author
explicitly refused to do the same for Devin, whose installer is a curl pipe bash:
`src/provider-onboarding.mjs:176-181` prints the command instead of running it,
commenting that running it unattended "would fetch and execute a remote script
the operator never saw". That is the right call and it is in the code.

## The question that mattered most: Anthropic. Clean.

**No path reads `~/.claude`. No reference to Claude Code credentials. No OAuth
flow for Anthropic anywhere in the tree.** `config/anthropic/anthropic.json` is
an ordinary API key provider pointing at `api.anthropic.com/v1` reading
`ANTHROPIC_API_KEY`.

The only home directories touched are `~/.codex`, `~/.kimi-code`, `~/.grok`,
`~/.dsh`, `~/.gemini` and `~/.config`.

**Harish will not trip Anthropic enforcement through this tool.** The
subscription exposure is OpenAI's, and that is finding 1.

## Installer and service, since these were the deciding items

**`install.sh`**, 325 lines, read line by line. No sudo. No curl piped to a shell
inside it. It clones or fast forwards `~/.local/share/codex-router` over git and
HTTPS, refuses if that directory holds a different repository, refuses to
overwrite tracked local edits without `--force`, never touches untracked files,
records a rollback ref before pulling, and restores the previous revision if
setup fails. No checksum or signature, because the artefact is a git pull, so
integrity rests on TLS and GitHub. It writes only to
`$XDG_DATA_HOME/codex-router`, `~/.codex`, `~/Library/LaunchAgents` and
`~/Applications`. Re runnable and idempotent. It backs up the original Codex
config to `config.toml.pre-codex-router` and chmods both to 0600.

**Background service.** A user LaunchAgent in `~/Library/LaunchAgents`, gui domain.
**No LaunchDaemon, no root.** `RunAtLoad` and `KeepAlive` both true. It spawns
six processes on ports 4200, 4201, 4202, 4203, 4208 and 4210. **Every one binds
127.0.0.1**, and LiteLLM is spawned with an explicit `--host 127.0.0.1` rather
than left on its 0.0.0.0 default. Every port requires authentication; the router
401s everything except `GET /health`.

**Credentials.** Plaintext files under `~/.codex/codex-router` at 0600 inside a
0700 directory, written atomically through a temp file. Resolution order is
environment, then file, then macOS Keychain. **Keychain reads are read only and
namespaced** `codex-router-<provider>`; it never writes a Keychain item. Keys are
never logged.

**Both README claims verified against code rather than trusted.** The hidden
prompt opens `/dev/tty`, runs `/bin/stty -echo`, reads byte by byte and restores
on every signal path. **There is no flag or argument that accepts a key on a
command line**, so a key cannot arrive through an agent's tool call.

**Supply chain.** Two direct npm dependencies, five packages total, all integrity
hashed, **no postinstall script anywhere**. `requirements/python.txt` is 114
packages with 2480 sha256 hashes installed with `--require-hashes`. The Homebrew
formula pins all 104 PyPI resources by sha256.

## Required changes before adopting

**a. Make the ChatGPT session fallback default to off.** Either change
`src/codex-native-session.mjs:34` to require an explicit opt in, which is the
honest fix, or add `CODEX_ROUTER_NATIVE_SESSION_FALLBACK` to the values object in
`src/service-macos.mjs:47` so the plist carries it and a reinstall stops
reverting it. **Harish uses GLM and DeepSeek through this and gains nothing from
the fallback**, so this is pure downside for him.

**b. Never enable the `github-copilot` provider** while `GITHUB_TOKEN` or
`GH_TOKEN` is in his environment, or strip those two names from
`config/github-copilot/github-copilot.json:22` in the fork. He has `gh`
installed.

**c. Decline the OAuth provider paths that trigger `npm install -g`**, and the
DeepSeek Harness target. He wants DeepSeek and GLM through their platform API
keys, which use the hidden prompt and install nothing.

**d. Pin the fork's `main` to `9995c77`** and set `CODEX_ROUTER_REPOSITORY_URL`
to the fork in the environment used for updates, or `bin/update` refuses to run
(finding 9).

**Optional, for the tightest posture:** decide whether the unconditional Codex
app tool relay in finding 2 is acceptable before pointing a third party model at
repositories that matter.
